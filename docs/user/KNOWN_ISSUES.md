## FLUX-KI-001 — Ollama Gemma 4가 이미지 첨부에 빈 답변을 반환함

| 항목 | 내용 |
| --- | --- |
| 상태 | 재현됨 · 외부 의존성 |
| 영향 범위 | Ollama의 gemma4:e2b, gemma4:e4b로 이미지 첨부 대화를 보낼 때 |
| 증상 | Ollama가 HTTP 200으로 요청을 완료하지만 최종 답변인 message.content가 비어 있어 답변이 생성되지 않음 |
| 데이터 영향 | 없음. 첨부 파일과 대화 기록은 보존됨 |
| FLUX 처리 | 일반 대화에서는 빈 답변을 저장하지 않고 실패 원인을 표시한다. 프로젝트 단체방에서는 0.3.0부터 설정된 횟수만큼 자동 재시도한 뒤 실패 기록을 남긴다. Ollama 오류에는 모델명, 스트림 이벤트 수, 보이는 문자 수, thinking 문자 수, 종료 사유만 기록한다. |

### 원인

FLUX가 사용하는 표준 Ollama api chat 이미지 요청은 서버까지 정상 도달합니다. 문제는 Ollama/Gemma 4가 일부 비전 요청에서 최종 답변 없이 완료되는 동작입니다. Gemma 4의 thinking 출력이 생성 토큰 예산을 모두 사용해 content가 비는 유사 사례가 Ollama에 보고되어 있습니다. [Ollama 이슈 16184](https://github.com/ollama/ollama/issues/16184)를 참고하세요.

### 임시 우회 방법

1. 이미지 분석에는 해당 모델 대신 검증된 멀티모달 모델 또는 외부 API 모델을 선택합니다.
2. 텍스트 요청도 반복적으로 빈 답이 나오면 Ollama 모델과 서버를 업데이트하고, 더 작은 입력 또는 더 큰 문맥·출력 예산으로 다시 시험합니다.
3. 프로젝트 단체방에서는 멤버 설정의 빈 응답 자동 재시도를 1~2회로 설정할 수 있습니다. 시간 초과는 자동 재시도하지 않습니다.
4. 2026-08-25 최소 텍스트 요청으로 gemma4:e2b의 정상 응답을 확인했습니다. 따라서 모든 요청에서 발생하는 오류는 아니며, 큰 프로젝트 문맥·이미지 입력·Ollama 서버 상태별 재현 여부를 위 진단 기록으로 구분합니다.

## FLUX-KI-002 — 협업 실행 기록은 모델 응답·도구 실행의 감사 기록이지, 코드 작성자를 암호학적으로 증명하지는 않음

| 항목 | 내용 |
| --- | --- |
| 상태 | 설계 제한 |
| 영향 범위 | 프로젝트 단체방에서 파일 변경을 요청한 경우 |
| 증상 | 기록에는 최종 superior 세션, 협업 실행 ID, 공급자·모델, 승인 결과가 남지만, 여러 모델의 의견이 최종 파일의 어느 줄에 반영됐는지 자동으로 증명하지는 못함 |
| 데이터 영향 | 없음 |
| FLUX 처리 | 선택적 첫 줄 출처 주석과 내부 변경 출처 기록을 제공한다. 멤버는 분석 전용이며 직접 파일을 수정하지 않는다. |

향후에는 실제 적용 모델과 협업 참여 멤버를 코드 출처 주석과 변경 기록에 더 명확히 넣는 방식을 별도 설계합니다.
