# 0.3.0 베타 — 프로젝트 단체방

## 현재 설계 (beta.5)

프로젝트는 하나의 **단체방**이다. 기존 일반 대화는 독립 대화로 유지하며, 프로젝트 안에서는 별도 하위 대화를 새로 만들지 않는다.

```text
프로젝트 단체방
  [user]       사용자
  [superior]   프로젝트 최상위 조정자 (사용자 바로 아래)
  [member]     최대 4개의 역할별 LLM
```

- 프로젝트 생성 시 `superior` 대화가 자동으로 하나 만들어진다.
- 기존 하위 대화와 그 기록은 삭제하지 않는다. 다만 새 프로젝트 UI에서는 단체방 하나만 표시한다.
- 메시는 단체방 타임라인 하나에 저장하며, `user` / `superior` / 각 `member`의 발신자 메타데이터와 협업 실행 ID를 함께 남긴다.
- 활성 멤버가 있으면 협업은 별도 토글 없이 자동으로 실행한다.
- 멤버는 발언 순서대로 **순차 실행**된다. 이전 멤버 보고는 다음 멤버와 superior에게 참고 자료로 전달된다.
- 각 멤버는 역할, 공급자, 모델, 활성 여부, 발언 순서, 응답 제한(1~300초), 다음 멤버 전 대기(0~300초)를 설정할 수 있다.
- 제한 시간 안에 끝나지 않은 멤버는 `timed_out`으로 기록하고 다음 멤버로 넘어간다. 전체 실행 기록에는 상태·모델·소요 시간·오류가 남는다.
- 멤버는 분석 전용이다. 파일 도구나 승인 결정을 수행할 수 없고, 최종 superior만 기존 파일 승인 정책을 사용할 수 있다.

## 검증 기준

1. 서로 다른 프로젝트는 서로의 멤버·타임라인·협업 실행 기록을 공유하지 않는다.
2. 같은 프로젝트에서는 멤버 보고가 설정 순서대로 한 타임라인에 남는다.
3. 중간 멤버 실패·시간초과가 나도 이후 멤버와 superior 최종 응답은 계속 가능하다.
4. 실행 중 상태 화면은 멤버 이름, 상태, 모델, 소요 시간을 표시한다.
5. 프로젝트 삭제는 실제 작업 폴더와 보존된 대화를 지우지 않는다.

## 이전 베타 호환

- beta.2~beta.4의 프로젝트 리더·하위 대화 데이터는 그대로 보존한다.
- 새 UI는 리더 대화만 프로젝트의 단체방으로 표시한다.
- 기존 하위 대화는 일반 대화처럼 직접 열어 보존된 내용을 확인할 수 있지만, 새 협업 멤버로 자동 실행되지는 않는다.

## beta.4에서 유지되는 제어 기능

- 대화별 요청 제한과 최소 전송 간격
- 생성 중 즉시 지시와 이전 승인 요청 안전 만료
- 파일 변경 출처 기록과 선택적 코드 주석
- Linux/Windows CLI PATH 등록
